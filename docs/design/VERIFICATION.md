# Design system — verification

## 購入導線のアクセシビリティ自動検査と修正 — 2026-09-14

P0-19（商用UI・アクセシビリティ）の一部として、プレビュー環境の購入導線10画面を axe-core 4.13.0 で検査しました。対象は、ホーム、商品一覧、M商品詳細、ギフト入力、カート（商品あり・空）、お届け先入力、注文内容の確認、テスト決済、テスト注文完了、404です。axe-core は既存の依存関係に含まれていたもので、新しい依存関係は追加していません。検査中だけ `public` に一時的に置き、検査後に削除しました。

**修正前の結果**：違反は全画面共通の1件でした。

- `region`（moderate）：サービス情報の帯 `.service-bar` が `div` に `aria-label` を付けただけで、ランドマークの外にありました。

**axe では検出されない問題として、次の2件も見つかりました。**

- ギフト入力と404の `<title>` が、ホームと同じサイト既定の値でした。読み上げやブラウザー履歴でページを区別できません。
- スキップリンクを Enter で押すと、URLのハッシュは変わりますが、フォーカスは `BODY` に残りました。`main` にフォーカスを受け取る設定がないためです。

**修正**

- 帯を `aside`（ラベル付きのランドマーク）に変更しました。見た目は既存の `.service-bar` クラスのまま変わりません。
- `main#main-content` に `tabIndex={-1}` を付け、スキップリンクでフォーカスが本文へ移るようにしました。本文全体に輪郭が出ないよう、`main[tabindex="-1"]:focus` の輪郭だけを消しています。
- ギフト入力は「（商品名）のギフト設定」、404は「ページが見つかりません」をタイトルにしました。ギフト入力は検索に載せない設定を維持しています。

**修正後の確認（ローカル本番ビルド、ポート3041）**

- 10画面すべてで axe の違反は0件でした。
- Tab で最初にスキップリンクへ届き、2pxの `--accent` の輪郭が表示されます。Enter で `main` にフォーカスが移り、`main` に輪郭は出ません。
- ギフト入力で宛名と贈ることばを空にして送信すると、最初の不正な項目（宛名）にフォーカスが移ります。2項目に `aria-invalid="true"` が付き、エラー文は `role="alert"` で読み上げ対象になります。このエラー状態でも axe の違反は0件です。
- 320px幅で、ギフト入力・注文内容の確認・テスト決済に横方向のはみ出しはありません。帯の高さは修正前と同じ28pxです。
- 通常テスト1124件、`tsc --noEmit`、`eslint`、静的検査5種、本番ビルドが成功しました。新しいテストでは、ギフト入力と404のタイトルを確認しています。

購入画面の保存データには、架空の検証用データだけを入れました。検証後に消去しています。

**未確認の範囲**：自動検査で見つかるのは問題の一部です。次の確認は残っています。

- 実機Safari・VoiceOver・NVDA による読み上げ
- ブラウザー設定での200%拡大
- 実Stripe経路の画面、発送・返金・取消の状態
- 色の知覚だけに頼らないかどうかの目視での網羅確認

戻す場合は、この変更をrevertします。DB、環境変数、依存関係の変更はありません。

## スマホのページ端の動きを抑制 — 2026-09-13

ルートの `html, body` に `overflow-x: clip` と `overscroll-behavior: none` を指定し、ページ全体の横移動と端の跳ね返り・引っ張り更新を抑えます。高さ固定やタッチイベントの遮断を追加せず、通常の縦スクロールと拡大操作を保ちます。

- 独立したローカル本番ビルドをPlaywrightのChromium / WebKitで確認。ホーム・商品一覧・M詳細・Lギフト・カート・未ログインのマイページを320／390／768／1440pxで検証し、48条件すべてで文書幅と画面幅が一致。ルートとbodyのCSS適用、横位置0、縦スクロール、追従ヘッダーを確認。[計測記録](evidence/mobile-scroll/measurements.json)。
- 320pxではメニュー開閉とEscapeでの復帰、ギフト入力欄へのフォーカスと画面内への収まりを確認。Chromiumのタッチ入力で縦に510px移動し、ピンチ操作後の表示倍率は約1.5倍。WebKitでは拡大禁止がないviewportとタッチ設定を確認したものの、実機Safariのゴムのような跳ね返りやOSのジェスチャーは未検証です。
- 画面記録：[Chromiumホーム](evidence/mobile-scroll/chromium-home-390.png)、[WebKitホーム](evidence/mobile-scroll/webkit-home-390.png)、[Chromiumギフト](evidence/mobile-scroll/chromium-gift-320.png)、[WebKitギフト](evidence/mobile-scroll/webkit-gift-320.png)。宛名などの個人情報は入力していません。
- `pnpm check:ci` 成功：通常テスト948件、DB専用198件skip、型・Lint・静的検査・本番ビルド。検証開始時にmainの送料エラー文言がスキーマから欠落して型エラーとなっていたため、既存JSONと利用箇所に対応する `cart.shippingUnavailable` の検証定義を復元しました。送料計算・注文処理は変更していません。
- 依存関係・DB・環境設定の変更なし。戻す場合はスクロール用CSSと対応するガイド・証跡をrevertし、ビルド修復用の文言定義は維持できます。本番へのマージ・デプロイは行っていません。
