# 友人紹介特典

## 現在の提供範囲

2026-09-11時点では **Test Mode専用**。`/referrals` から紹介リンク発行、友人の特典受取、テスト購入の値引き、配達完了後の紹介者特典、返金時の無効化を試せる。実際のクーポン発行・請求・配送は行わない。既存の本番販売・決済ゲートは変更していない。

設計判断: [ADR 0004](../architecture/adr/0004-referral-rewards-preview.md)。決済連携の進捗とは分けて扱い、このプレビューをそのまま本番で有効にしない。

## 採用した特典と狙い

| 対象 | 特典 | 条件 |
| --- | --- | --- |
| 紹介された友人 | 初回購入の商品代金から500円引き | 初回購入前に紹介コードを受け取る |
| 紹介した利用者 | 次の購入で使える500円引き | 友人の対象初回注文がお届け完了になる |
| 共通 | 商品小計5,500円以上、送料対象外 | 1注文1枚・他特典と併用不可・受取から90日間 |
| 紹介者の付与上限 | 月5件 | お届け完了を処理した月、Asia/Tokyo基準 |

友人の初回購入の負担を下げ、紹介者には次の贈りものを選ぶ動機をつくる。割合割引より金額が伝わりやすく、紹介1件の特典額は最大1,000円に限定できる。紹介者分の利用にはさらに5,500円以上の購入が必要。ただし原価・送料負担・既存顧客の置換効果は未確認で、利益改善が証明された制度ではない。本番前に粗利と獲得費用を確認する。

## 詳細ルール

- 紹介先は最初に受け取った紹介者に固定。同じコードの再受取は重複発行や期限延長を起こさない。自分のコードは使えない。
- 初回判定は現在のテスト利用者で記録された最初のテスト購入。特典を使わない購入や最低金額未満の購入も初回枠を消費する。後から紹介コードを受け取っても初回特典は発行しない。
- 友人が特典を使わなくても、紹介済み・初回・商品小計の条件を満たす注文のお届け完了は紹介者の付与対象。友人クーポンの有効期限と紹介の紐付けは別。
- 複数枚ある場合は有効期限が近い利用可能な1枚を適用。自動確定はせず、テスト決済画面の「紹介特典を確認・利用する」で金額を確認できる。
- 期限切れ、使用済み、所有者違い、商品価格変更は確定前に拒否する。確認後に失効した割引を黙って外して決済しない。
- 配達前のキャンセル・返金は付与しない。付与後は未使用特典を無効化し、既に使われた特典は要確認として記録する。過去の注文金額を勝手に書き換えたり、追加請求したりしない。
- 返金による初回枠や使用済みクーポンの復活はない。無効化済みの付与も月間5件に数える。上限到達時の注文を翌月に繰り越して付与しない。
- 同じ注文・配達・返金を繰り返しても重複付与しない。既存注文の所有者・商品・数量・小計・クーポンが変わった再実行は拒否する。

## ローカルで試す

1. runtimeとcheckout providerが両方 `preview` の環境で `/referrals` を開く。
2. 紹介リンクを作成し、リンク内の `BB-` から始まるコードを控える。
3. 「紹介の流れを試す」から「友人役のテスト利用者を作る」を選ぶ。控えたコードで初回特典を受け取る。別のブラウザから同じサーバーの紹介リンクを開いて受け取る方法でもよい。
4. 商品小計5,500円以上の花を選び、架空の情報でテスト購入に進む。決済画面で特典を確認し、500円引きの合計を確認して成功シナリオを実行する。
5. 完了画面で「お届け完了を再現」を押す。紹介ページに戻り、「前のテスト利用者に戻る」で紹介者の特典を確認する。
6. 友人役に再度切り替え、同じタブの `/checkout/test/complete` で返金を再現する。紹介者の未使用特典が無効になったことを確認する。

## データ・障害・変更方法

- 数値条件は `src/modules/referral/domain/referral-policy.ts`、表示文は検証付きの `content/referral.json` に集約。画面の金額・日数は同じポリシーから埋め込む。
- メモリ保存で永続性・複数サーバー間共有はない。再起動・デプロイで失われる。テスト利用者は1日有効のHttpOnly Cookieで識別し、期限切れやCookie削除で特典にアクセスできなくなる。90日は制度ルールの検証用であり、プレビュー保存期間の保証ではない。
- 1プロセスで利用者1,000件・注文5,000件まで。満杯の場合は新規記録を断るが、既存注文の同じ再実行は可能。上限は不正対策や永続的な監査の代替ではない。
- 個人情報は紹介状態へ保存しない。公開の紹介コードと秘密の利用者Cookieを分離する。紹介者には友人の氏名・住所・購入内容を表示しない。
- 特典サービスが利用不能な場合、利用者が「特典を使わずに進む」を明示すると、割引と紹介記録なしで従来のテスト購入を完了できる。この障害時購入の事後補填は未実装で、本番運用には使えない。業務上のクーポン不正・価格変更をこの経路で迂回しない。
- ブラウザ上のテスト利用者切替や配達・返金ボタンはサーバーでもpreview以外を拒否する。ブラウザに表示されないことだけを防御にしない。

## 本番提供までに必要な作業

| 必要な接続・運用 | 完了条件 |
| --- | --- |
| 顧客の本人性と購入履歴 | 認証済みのShopify顧客と結び付け、既存注文も含め初回判定。Cookie作り直しを新規顧客と扱わない |
| 不正利用対策 | 自己紹介・複数アカウント・相互紹介等を検知する基準、レート制限、最小限の個人情報、異議申立てと運営判断 |
| 永続台帳 | 紹介・特典・利用・取消の一意制約、同時実行トランザクション、監査履歴、バックアップと復旧 |
| Shopify割引連携 | 顧客限定・1回限り・最低金額・期限・併用設定を反映し、Shopifyの確定金額を採用。発行・取消の再試行、照合、不明結果からの回復 |
| 正式なイベント | 検証済みの支払・配達・取消・返金イベント、重複・順序逆転・遅延、部分返金・複数配送・紛争の条件。ブラウザ操作では付与しない |
| 運用と効果検証 | 要確認案件の処理画面、失敗通知、未付与の再処理、特典費用対粗利、紹介購入率・再購入率。分析障害で購入を止めない |
| テストストア検証と公開 | 実APIの隔離テスト、顧客間の漏洩防止、返金・再配達・期限・同時利用のE2E、規約と原資を確認して既存release gateを通す |

Shopifyの割引コードは、最低購入額・利用回数・対象顧客等を設定できる。ただし「顧客につき1回」はコード単位であり、この紹介制度全体の初回判定にはならない。個別コードの制限だけに頼らない。
公式仕様: [割引コード](https://help.shopify.com/en/manual/discounts/discount-methods/discount-codes)、[割引の組み合わせ](https://help.shopify.com/en/manual/discounts/discount-combinations)。
