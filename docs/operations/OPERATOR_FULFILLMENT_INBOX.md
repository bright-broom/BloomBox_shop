# 担当者の注文一覧

2026-09-12。`/operations/fulfillments` から店舗を指定し、受付済みの注文を探して発送前の確認画面へ進めます。[Google ログイン](GOOGLE_OPERATOR_LOGIN.md)で登録済みの担当者には、ログイン画面に「注文一覧」を表示します。詳細画面からも同じ店舗の一覧へ戻れます。

## 表示と権限

店舗の myshopify.com ドメインを入力すると、ログイン状態、Google subject と内部担当者 ID の対応付け、店舗別の有効な閲覧権限をサーバーで検証します。未認証・未登録の要求では DB 接続を作成しません。権限行を共有ロックし、同時の失効操作を直列化します。ロック取得後と注文の読取後にセッション・権限期限を再確認します。

一覧は内部発送 ID、Shopify 注文参照、希望日、税込総額、保存済み発送状態、表示基準時刻に限定します。購入者・受取人の氏名、住所、電話、ギフト本文、決済トークン、承認キーは取得・返却しません。`OPERATOR_SHOPIFY_MODE` の test/live 区分と店舗を全ページで照合します。入金・在庫や承認可否は一覧では判断せず、[個別確認](SHOPIFY_FULFILLMENT_REVIEW.md)へ進んで確認します。

最初は権限のある店舗のドメインを担当者が指定します。店舗一覧の自動取得、検索・絞り込み、未確認件数の集計は未実装です。存在しない店舗と閲覧権限のない店舗は同じ案内を表示します。認可済みで注文がない場合は空の一覧、取得失敗は機密情報を含まないエラーを表示します。

## ページ送り

1ページ20件、次のページの判定を含めても21件まで読み取ります。既存の `(provider_scope, external_order_id)` 一意インデックスに沿い、変更されない外部注文参照の文字列順で移動します。注文日時・配送予定日順ではなく、画面にも「注文参照順」と明記します。巨大な OFFSET や全件取得を使いません。新規インデックス・移行・追加権限は不要です。

カーソルは店舗、test/live 区分、最後の注文参照だけです。600文字までの構造と区分を検証し、別店舗・別区分への持ち越しや不正な入力を拒否します。署名付きの権限証明ではありません。値を変更しても毎回本人と店舗権限を検証し、参照位置以外の用途に使いません。

同じ受付の状態・版が更新されてもページ順は変わりません。複数ページをまたぐ固定スナップショットではないため、既に通過した位置への新規追加は「最初から読み直す」で取得します。ブラウザーの履歴から戻った内容も最新の在庫・権限の保証には使えません。ページとリンクは自動先読みをせず、サーバー応答は既存の private/no-store、no-referrer、noindex を引き継ぎます。

## 検証・戻し方

- `pnpm check:ci`：通常632件、型・Lint・静的チェック・本番ビルド成功。
- 隔離 PostgreSQL：89件成功。20件を超える複数ページ、重複・欠落、状態更新後の順序、test/live 分離、別店舗、未知・不正カーソル、次ページ取得前の失効、実際の権限ロック競合と期限切れ、専用ロールの読取、Outbox 非生成を検証。
- ブラウザーはローカルの本番ビルドと隔離 DB の架空注文・架空認証セッションで検証します。実 Google ログイン・実店舗の検証の代用ではありません。

追加の環境変数、依存、移行はありません。Google OAuth と実店舗権限の登録は引き続き必要です。戻す場合は一覧へのリンクと新規 Query/ルートの利用を停止します。`AUTH_OPERATOR_ENABLED=false` で担当者からのデータアクセス全体を閉じることもできます。注文・承認・監査履歴を削除する必要はありません。承認ボタン、発送実行、本番 Gate は変更していません。

Chrome の320/1440pxで、一覧20件→重複のない次ページ→詳細→同店舗の一覧への復帰を確認しました。横はみ出し・ページエラーなし。匿名アクセス、権限のない店舗の拒否、private/no-store・no-referrer・noindex も確認済みです。[モバイル](evidence/operator-inbox-mobile.png)／[デスクトップ](evidence/operator-inbox-desktop.png)は隔離 DB の架空注文です。検証用サーバー・一時 DB 接続ロールは検証後に停止・削除します。依存監査も既知の脆弱性なしでした。
