# 自作の商品カタログ

[ADR 0009](../architecture/adr/0009-native-commerce-and-google-customers.md)に基づき、商品の取得元をShopifyからPostgreSQLへ切り替えます。これは商品参照の移行です。在庫予約・販売開始・実商品の登録を完了したことを意味しません。

## 実装済みの動作

- 本番モードの商品一覧・検索・詳細は `catalog_products` を参照します。Shopify Storefrontの設定や通信は不要です。Previewは引き続き既存のJSONとメモリを使用します。
- DBは空で作成されます。Previewの商品、価格、花材、在庫数を自動で取り込みません。DB未登録時は空の結果、障害・不正データの場合は明確なエラーにし、サンプルへの代替表示を行いません。
- 新規行は下書き（DRAFT）・受付不可（available=false）が初期値です。公開（PUBLISHED）の商品だけを詳細で参照でき、公開かつ受付可の商品だけを一覧・検索に出します。非公開（ARCHIVED）はID・URLを直接指定しても参照できません。
- `available` は運営側の受付可否であり、残在庫数や予約完了を意味しません。在庫予約が未完成のため、本番モードの新規購入は `BLOOMBOX_CHECKOUT_INTAKE_ENABLED=true` でもアプリケーションで停止します。既存取引のWebhook受付・決済照合・保持期限処理は停止しません。
- 商品IDは独立したUUIDから作る `native_<UUID>` です。ShopifyやPreviewのIDを解釈し直したり、過去の注文の商品参照を書き換えたりしません。
- 価格はJPYの整数で、サーバーがDBの値から計算します。購入情報へ保存した価格は後から商品価格が変わっても維持します。送料・税・在庫の確定は別の責務です。
- 商品画像はNext画像配信設定と共有するHTTPSの許可ホストだけを受け付けます。現時点の許可先は `images.unsplash.com` です。正式な画像保存先を決めたら、設定変更と検証を行います。
- 一覧は最大1,000商品です。上限超過や不正な商品情報を黙って除外せず、エラーにします。

## DB適用と権限

`0019_native_catalog.sql` を既存のマイグレーション手順で適用し、続いて `database/roles.sql` を適用します。既存テーブルと既存の注文・決済情報は変更しません。適用済みの過去マイグレーションも変更しません。

アプリケーションと決済ワーカーには新しい商品テーブルのSELECTだけを付与します。既存の出荷承認者や権限管理者へ商品編集権限は追加しません。DB所有者以外の編集経路・管理画面・一括登録コマンドは未実装です。運営者向けの商品編集では、専用権限、versionによる競合検知、価格・公開状態の監査記録を組み込む必要があります。

## 検証と未完了事項

専用ローカルPostgreSQLで、マイグレーションの再適用、空の初期状態、下書き・非公開の遮断、受付不可商品の詳細、検索、JPY価格の制約、購入時価格の保持、不正な画像や商品データ、件数上限、権限による書き込み拒否、読取障害からの復旧を検証します。CIはPostgreSQL 16を使用します。

公開条件は `config/production-commerce-activation.json` の `nativeCatalogContract` を含む8項目のままで、すべて未承認です。Shopify用の商品証跡は自作カタログの証跡へ名称を変更しましたが、完了扱いにはしていません。

残作業は、実商品の承認・登録と画像保存先、運営者の商品編集、同時購入に対応する在庫予約・解放・確定、購入者紐付けの実接続検証、Stripeテスト決済、出荷運用、公開環境での検証です。在庫予約が実装・検証されるまで、本番モードの受付停止を解除しません。

## 戻し方

アプリケーションを直前の版へ戻し、新規受付を停止したまま調査します。商品テーブルと保存済みの商取引は削除しません。旧版の商品参照を使う場合は旧Shopify設定が必要です。コードの巻き戻しによって、作成済みの自作商品IDをShopifyへ変換しません。取引は最初に選択した決済先で照合を続けます。
