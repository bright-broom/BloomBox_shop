# Googleログインから本人のマイページまでの実接続

2026-09-14。コードは main `df7dda9d62ec41d916c5d42c54add01c4f92e7be`（PR #108）を使用。専用ログイン画面・マイページの実装に、既存の実Google OAuthと隔離した顧客DBを接続した記録です。今回のPRは文書のみで、認証コードを作り直していません。

## 完了した経路

```mermaid
flowchart LR
  Home[トップのマイページ] --> Entry[/account]
  Entry -->|未認証| Login[/account/login]
  Login --> Google[顧客専用Google認証]
  Google --> Callback[/api/customer-auth/callback/google]
  Callback --> Account[本人の購入履歴・会員ランク・プロフィール]
  Entry -->|認証済み| Account
  Account --> Detail[本人の注文詳細]
  Account -->|ログアウト| Login
```

入口と認証後の画面は、それぞれ `/account/login` と `/account`。`/preview/account` は引き続き架空のデザイン見本です。実Google認証で入った `/account` は顧客IDを検証し、その顧客のDB情報を読みます。

## 接続した設定

- 既存の顧客用Google OAuthクライアントへ `http://localhost:3025/api/customer-auth/callback/google` を追加し、Google Cloudの保存完了と実際の認証成功を確認しました。以前の3000番callbackも維持しています。
- 既存の管理者用クライアントにも `http://localhost:3025/api/operator-auth/callback/google` を追加。顧客用とは別クライアント・秘密値・Cookieを維持しています。対象ユーザー・スコープ・公開範囲の変更、新しい秘密値の発行はしていません。
- 起動するサーバーの `CUSTOMER_ACCOUNT_ORIGIN` と `AUTH_URL` を `http://localhost:3025` に統一し、既存の顧客用認証設定を接続しました。秘密値はGit対象外、所有者のみが読める環境ファイルで保持しています。
- 既存の隔離顧客DBへ接続。事前にローカルの非公開バックアップを取得し、未適用だった既存migration 0023〜0025を適用しました。新しいmigrationは追加していません。再実行時の追加適用は0件でした。
- アプリは既存の非superuserロールで接続します。既存の顧客2件・Google ID対応2件・接続確認用注文2件を維持し、顧客の作り直しや注文の追加はしていません。

## ローカル再開時の手順

今回のサーバーは `/private/tmp/bloombox-auth-routing` から3025番で起動し、同ディレクトリの `.env.local` を読みます。Googleへ登録したポートと異なるポートへ自動的にずらさないでください。別の作業ツリーを使う場合、コードだけでは秘密値は移らないため、その作業ツリーへ既存の非公開設定を安全に引き継ぐ必要があります。

1. 起動対象にPR #108以降のコードがあることを確認する。
2. 対象作業ツリーのGit対象外設定に、顧客認証・同じオリジン・DB接続があることを確認する。元リポジトリの未接続設定や、合成認証のテスト設定と取り違えない。
3. 顧客DBの稼働とmigration 0025までの適用を確認する。既存の初回DB作成・注文seedスクリプトは再実行しない。
4. 対象作業ツリーで `pnpm exec next start --port 3025` を使う。未buildの場合は先にbuildする。変更作業中は `pnpm exec next dev --port 3025` を使えるが、同時に同じポートを占有しない。
5. トップ→専用ログイン→実Google→本人のマイページを確認する。起動ログや設定の存在だけでは完了にしない。

ローカルDBと資格情報の管理メモは `/private/tmp/bloombox-customer-local/README.md`。秘密値そのものをチャット、ログ、PRへ貼らない。上記のローカルパス・稼働状態は、この確認日以降に再確認してください。

## 今回の範囲外と切り戻し

実認証は接続済みですが、表示した注文は以前の隔離DBの確認用注文であり、実Stripe決済や発送はありません。Googleの公開ステータスは「テスト中」、登録テストユーザー2名であることも確認しました。本番・Vercelの認証設定、本番HTTPS、一般公開、実決済と会員割引の一連の検証は別作業です。Previewモードと新規注文受付停止を維持しています。管理者の各業務機能への追加権限付与はしていません。

接続を停止する場合は、このローカルサーバーで `CUSTOMER_ACCOUNT_ENABLED=false` を反映して再起動します。Google側の3025番callbackを削除する場合は同じクライアントのそのURIだけを対象にし、既存の3000番設定や資格情報を削除しません。適用済みmigrationを削除したり、顧客・注文・監査記録を消したりする必要はありません。
