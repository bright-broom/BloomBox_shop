# 担当者権限の管理画面

2026-09-12。`/operations/permissions` に、店舗別の権限確認・失効・直近履歴の画面を追加しました。[監査付き失効](OPERATOR_PERMISSION_REVOCATION.md)を既存のGoogleログインと接続しています。実Google接続情報、実管理者の指定、実権限の変更は行っていません。

## 利用者と表示

Googleの検証済みログイン、許可メール、subjectと担当者UUIDの明示的な対応付け、店舗別の有効な管理権限が必要です。通常の注文確認・承認権限では開けません。担当者ログイン画面から移動できます。認証や管理権限が不足する場合は管理専用の案内を表示し、権限一覧や操作用の確認情報を返しません。

最初に開く店舗は、管理できる店舗のうちドメイン順の先頭です。画面に対象店舗を明示し、別店舗への切替にもその店舗の管理権限を要求します。1ページ20件で、表示位置は読み取り位置にすぎません。管理権限はページごとにロックして再検証し、読み取り後のDB時刻でも期限を確認します。

表示するのは担当者の登録番号、権限の状態・期限・確認版、直近の失効実施者の登録番号・理由・時刻です。登録番号は内部UUIDです。管理台帳で本人と照合してください。氏名、メール、Google subject、顧客・配送先情報を一覧に混ぜません。最新の失効履歴は過去の判断として表示し、再有効化後の現在状態と区別します。

## 操作と再送

有効フラグが立つ対象には、確認した店舗・対象・版を暗号化した送信情報をサーバーで発行します。現在の担当者、ログイン期限、test/live設定、用途専用の鍵とaudienceに結び付け、期限は最大5分かつ元のログイン期限までです。ブラウザーで対象・担当者・版を追加指定しても採用しません。

失効には固定の理由選択と確認チェックが必要です。理由を変えた場合はチェックを外し、確認し直してもらいます。送信中は操作を止めます。エラー後のフォーム自動リセットを抑止し、同じ確認情報・理由・チェック状態を保持します。成功後は操作欄を閉じ、最新の権限と履歴を表示します。保存後の画面更新だけが失敗しても、保存成功を失敗として扱いません。

Server Actionは正規Origin、現在のログイン、入力項目と個数を検証します。その後、担当者ごとの[直近60秒・10回の共通枠](OPERATOR_APPROVAL_RATE_LIMIT.md)を消費して、暗号化された確認情報と既存の失効コマンドを検証・実行します。承認と失効は同じ枠を共有します。旧来の表名 `fulfillment_approval_submission_limits` は維持し、別の無制限経路を作りません。DB障害時のフォールバックはありません。

失効は店舗の承認権限を取り除く操作で、test/liveの両方に適用されます。事業方針PENDINGでも、正しく設定された管理者によるアクセス解除は可能です。権限の付与・再有効化・管理者登録・発送には接続しません。元の確認情報が古い、別の変更が入った、再ログインした場合は最新の権限と履歴を確認してください。

## 接続と移行

- 前進移行0017で店舗別一覧と最新失効履歴の索引を追加します。0016までの移行内容は変更しません。
- `database/roles.sql` を再適用します。管理用NOLOGINロールに、既存の送信枠を読む／消費する権限を追加します。承認や注文への書込権限は追加しません。
- サーバーの秘密管理に `DATABASE_PERMISSION_MANAGER_URL` を設定します。既存の `DATABASE_OPERATOR_URL`、一般アプリ・worker・DB所有者の接続を流用せず、`bloombox_permission_manager` だけを付与した専用ログインを使います。承認用と管理用の接続先は同じBloomBox DBである必要があります。
- 未設定・不正な接続では拒否し、他のURLへフォールバックしません。接続プールは既存のSSL・接続数設定を利用します。資格情報を更新した場合はプロセスも更新してください。
- 実管理者の指定と店舗別管理権限の初期登録は別途必要です。今回は合成データの隔離検証のみで、実アカウントへの付与はありません。

画面とActionの応答には既存のprivate/no-store、no-referrer、noindexを適用します。Next.jsのストリーミングではNot Foundの画面がHTTP200で返る場合があるため、拒否の検証ではHTTP番号だけでなく、拒否画面と保護データ・フォームの不在を確認しています。

## 検証

通常688件・隔離PostgreSQL120件、型・Lint・静的検査・本番ビルドが成功しました。DBでは全17移行の再適用、ページ境界、店舗分離、最小の表示情報、読み取りによる監査件数不変、失効履歴、ロック待ち中の管理権限失効、承認／管理接続での共通送信枠を検証しています。

隔離DBと合成ログインCookieを使った本番ビルドのChrome確認では、320/1440pxの横はみ出し・実行エラーなし、匿名／一般担当者の拒否、private応答、理由選択と確認、監査書込失敗時の巻き戻し、同じ理由・確認情報での再送、失効成功と履歴表示を確認しました。画像：[モバイル](evidence/permission-management-mobile.png)／[デスクトップ](evidence/permission-management-desktop.png)／[失効後](evidence/permission-management-recorded.png)。すべて架空の登録番号です。

実Server ActionへのHTTP要求でも、重複の成功応答、理由変更の競合、改ざん・未確認・匿名・別担当者・異なるOriginの拒否、頻度制限、失効記録1件のみを確認しました。これは実Googleの同意画面や実店舗での成功証跡ではありません。

## 戻し方と残件

管理画面／Actionの接続を止めるか、管理者の店舗権限を無効にします。追加索引・既存表・失効履歴・監査は保持し、失効済みの権限を戻しません。[担当者単位の全セッション失効](OPERATOR_SESSION_REVOCATION.md)は後続実装済みです。[DB所有者向けの権限登録・更新ツール](OPERATOR_ACCESS_PROVISIONING.md)は後続実装済みです。実Google接続、実管理者と店舗の指定、端末別セッション失効の評価、実店舗でのE2Eは残件です。本番の販売・承認Gateは変更していません。
