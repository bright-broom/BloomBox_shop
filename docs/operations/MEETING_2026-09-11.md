# 2026-09-11 会議内容の開発反映

## 採用方針と今回の確定事項

現在の正本は [ADR 0003](../architecture/adr/0003-shopify-payments-and-komoju.md) の Shopify Checkout + Shopify Payments + KOMOJU。会議の独自EC + Stripe案は最終決定の記録ではなく、後継ADRもないため切り替えない。Vercelのプレビュー配備は実決済の成功証跡ではない。Shopifyと独自DBを同じ注文・在庫の正本にしない。

会議反映中のユーザー回答で価格案の了承を確認した。Mは商品4,000円 + 送料1,000円 = 5,000円、Lは商品8,000円 + 送料0円 = 8,000円。2026-09-12のユーザー回答で、税込・日本全国配送を確定した。配送地域の除外は設けない。複数箱の送料、花材・内容量・箱寸法は未確定。本番へは適用せず、テスト購入で上記の合計を確認する。複数箱について新しい配送条件を約束しないため、この初期プレビューは1箱ずつに限定する。

紹介特典の最低商品小計は **5,500円を維持**するとの回答を確認した。Mの1箱購入は利用・紹介成立の対象外。Lは他の条件を満たす場合、500円引きで7,500円になる。送料を最低購入額へ足さない。従来の90日・月5件・併用不可・配達後付与・返金処理を維持する。

## 実装と利用方法

`/flowers` でM/Lを比較し、サイズの購入ボタンからギフト入力へ進む。入力画面内のサイズ選択を変更しても、宛名・希望日・メッセージは消えない。保存するまでは既存カートを変更しない。保存済みの別サイズから入り直した場合も、同じファミリーのギフト入力を引き継ぐ。

チェックアウトの金額は、ブラウザの価格・送料・割引を採用せずサーバーのカタログと特典状態から確認する。確認した小計・送料と一致しない場合は拒否する。同じ注文IDでサイズ・価格・送料・特典が変わった再実行を拒否する。旧デモの送料1,100円は旧保存データの互換用で、新しいM/Lへ適用しない。

`/preview/gift-experience` はpreview環境だけの確認ページ。待機表示の見本、受取人案内、紹介特典、動線確認をまとめている。「動線の確認を開始」したタブで購入を試し、戻って集計する。200件で追加記録を止め、停止操作で削除する。注文開始・テスト完了はrequest IDごとに一度だけ記録し、過去の重複防止記録を上限到達時に押し出さない。氏名・メール・住所・電話・ギフトメッセージ・紹介リンク・実Shopify cart IDは記録しない。ブラウザ保存の失敗は購入を止めない。

これは検証用の操作カウントであり、実顧客の人数・獲得・広告貢献・売上の分析ではない。複数タブ・再訪・同一人物は識別しない。受取人特典は未発行なので、その利用イベントも発生しない。本番の購入イベントは将来の検証済み注文イベントから一度だけ生成する。

`/gift-next` は共通の受取人向け案内。元の購入を識別するURLパラメータやCookieを使わず、顧客登録もしない。最終公開ドメインとカード印刷仕様を決定してからURL/QRを印刷する。個別特典の権利をこの共通URLだけで与えない。

## 変更箇所と境界

| 管理対象 | 正本 |
| --- | --- |
| プレビュー商品・価格・サイズ別送料 | `content/catalog.json`、CatalogのZod検証。`previewOffer` はプレビュー用のサイズSKU情報で、Shopifyのデータではない |
| 金額整合・1箱制約 | Checkoutの `domain/preview-pricing.ts`。実Checkoutの税・地域送料はShopifyが正本 |
| 既存の注文スナップショット | 選択したSKU ID・名称・単価をPurchaseIntentに保存。サイズ変更で新しい操作IDを発行 |
| 読みもの・案内・比較画面のコピー | `content/gift-experience.json`、Zodスキーマ |
| ブランド紹介 | `content/storefront.json` のabout、税未確定のguideコピー |
| 包装と合わせる色・書体・余白・角丸 | `src/app/globals.css` の既存トークン。今回の共通レイアウトもトークンを利用 |
| 紹介条件 | 既存 `referral-policy.ts`。新しいクーポン方式・ポイント台帳は追加しない |

初期プレビューは1商品を2つの購入可能SKUとして表現する。既存のProduct/PurchaseIntentは1つの販売単位を扱うため、選択サイズを曖昧な自由記述にしない。本番のShopifyアダプタは依然として1商品1variantの制約があり、本番M/Lの2variant取得・選択・在庫・Shopify cartへの引継ぎは残件。今回の `previewOffer` を本番アダプタから生成したり、本番の価格正本にしたりしない。

旧3商品のデモJSONは回帰テスト用fixtureへ移した。旧商品の保存カートは自動的に新しいSKUへ置き換えない。内容は保持しても、旧商品の新規購入準備は商品利用不可として拒否する。新しい商品へ入れ替える操作でのみカートを変更する。

## 本番購入基盤の既存実装と不足

| 確認した基盤 | 既存実装 | 不足・接続待ち |
| --- | --- | --- |
| 注文・支払・出荷の分離 | 独立状態機械、DBスキーマ、遷移・台帳 | Shopifyの正式なイベントからの投影 |
| 永続保存 | PostgreSQL migration、repository、暗号化 | 本番DB・権限・鍵設定、実復旧の証跡 |
| 在庫 | Shopifyを正本とする方針 | 同時購入、予約解放、遅延支払との整合と実店舗試験 |
| 決済通知と重複防止 | 直接Stripe用の署名検証・Inbox・再試行・再照合 | Shopify用の検証済み通知・冪等処理・再照合 |
| 決済済み未確定の回復 | Stripe向け再取得・照合と停止/再開境界 | Shopifyの結果不明状態・安全なcart資格情報保存・修復 |
| 確認・取消・返金・出荷 | 状態表示、既存Stripe通知処理、参照基盤 | Shopify管理への委譲範囲、正式な通知、権限付き出荷処理 |
| 管理・個人情報 | 購入者/受取人モデル分離、暗号化、一時データ削除 | 認証・サポート権限・保持方針。本番管理画面の重複開発はしない |
| 障害・復旧・負荷 | Smoke、構造化エラー、Worker関連運用 | 通知先、バックアップ復元、Webhook滞留、閲覧/購入別の負荷証跡 |

## 商品フィードと広告の準備

Shopify公式のGoogle & YouTubeチャネルは商品情報をMerchant Centerへ同期するため、独自フィードを先に増やさない。ただしヘッドレス画面のドメインがShopify設定と違う場合、商品リンクが一致しない可能性がある。公開ドメイン・商品URL・Merchant Centerのサイト確認を先に揃える。公式資料: [接続方法とヘッドレスの注意](https://help.shopify.com/en/manual/online-sales-channels/marketplaces/google/getting-setup/connect)、[商品同期](https://help.shopify.com/en/manual/online-sales-channels/marketplaces/google/getting-setup/syncing-products)。

| フィードで揃える情報 | 現状／確認事項 |
| --- | --- |
| 商品・サイズの識別 | 本番Shopify product IDとM/Lのvariant/SKU、共通の商品グループ。プレビューの `prod_bloombox_*` を広告のIDへ流用しない |
| 価格・税・送料 | 税込・日本全国配送、M/Lの上記価格はユーザー確認済み。Shopify店舗設定へ反映して実額を検証。複数箱の条件は未確定 |
| 在庫 | Shopifyの実在庫・販売可能状態。fixtureのavailableを配信しない |
| URL | 本番ドメイン、サイズ選択を再現できる商品ページ、Merchant Centerのサイト確認 |
| 画像・商品説明 | 実物のM/L、包装、内容差、許諾済み画像。現在のイメージ画像は広告商品の証拠ではない |
| GTIN等・返品・窓口 | 適用される識別子の有無を確認し、創作しない。正式な返品条件・実在窓口を整える |
| 広告・同意 | 所有するGoogle/Metaアカウント、権限、測定ID、同意・保持方針、予算の承認が必要。今回は送信・有料配信なし |

広告経由売上の割合は「広告に帰属する売上÷総売上」、広告費率は「広告費÷定義した対象売上」。分母、帰属期間、返品控除を明記し、両者を混同しない。

## 次に必要な判断とサイト外の作業

1. **購入基盤**：税込・日本全国配送の店舗設定と実額の確認、複数箱の料金、Shopify店舗と決済手段の審査・設定、本人確認・通知・返品運用。
2. **ギフト体験**：M/Lの花材・本数・内容量・箱寸法、固定方法、写真、包装・色・印刷、資材ロット/納期。ギフト/自宅用の用途と同梱物・物流出力の採用範囲。
3. **リピート**：受取人特典の方式・対象・金額/増量内容・原価・期限・回数・成立条件、印刷カードのURL/QR仕様。
4. **広告**：公式Instagram/FacebookのURL、Google/Metaの所有アカウント、同意と測定ID、Merchant Center、配信予算・担当。TikTokやフラワースクールの広告テスト、保守・障害対応・料金の担当分担はサイト外で決める。

Bonpoint専用の会員統合・Clarity・LINE・誕生日クーポン・楽天ペイ等は本実装の対象外。個人データの統合、アプリ導入、投稿、広告配信は実行していない。

## 検証とロールバック

- ブラウザでM→L→Mの切替と入力保持、Mの5,000円での購入完了、失敗後再試行、Mの紹介割引除外を確認。Lの8,000円表示と7,500円のサーバー決済計算はテストで確認。
- 再読込後のテスト購入集計は1件。受取人ページは特典利用不可・元購入の情報なし。320px/390px/1280pxで確認し、320pxの文書幅とスクロール幅が一致。Tabでフォーム移動、入力エラー時のフォーカス移動と読み上げ用のラベル/alert/statusを確認した。VoiceOverによる実読み上げと実機検証は未実施。
- 既存の `prefers-reduced-motion` ルールが共通花マークにも適用されることをコードで確認。ブラウザのOS設定を変更した試験は未実施。
- 自動検証は `pnpm check:ci`。型・lint・境界・デザイン・ハードコード・内容検証、単体テスト、本番ビルド。既存DB7テストはローカル未設定時はスキップし、CIのPostgreSQLで検証する。実Shopify/Stripe決済は未試験。
- 最終ローカル実行: `pnpm check:ci` 成功、245テスト成功・既存DB7テストはスキップ、本番ビルド成功。
- 視覚証跡: [デスクトップ](evidence/meeting-sizes-desktop.jpg)、[スマートフォン](evidence/meeting-sizes-mobile.jpg)。

新しい秘密情報・サービス・依存パッケージ・DB migrationは不要。revertで従来のプレビューへ戻せる。新SKUの保存カートは旧版に存在しないので、利用者が商品を選び直す必要がある。実決済・本番データへの変更はない。
