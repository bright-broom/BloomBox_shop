# テスト購入操作とカートの照合

2026-09-12。テスト用紹介特典サービスの応答が遅れた場合も、支払操作を開始したカートだけを完了できるようにする。

## 問題と修正

通常の特典確定結果にはrequestIdが含まれ、保存直前にカートと照合していた。一方、「特典を使わずに進む」を選択し、サービスが利用不可を返した経路には確定結果がない。その間に別の操作で新しいカートが保存され、入力・確認まで済むと、古い操作から新しいカートを完了し、入力情報を削除できてしまった。

支払画面は操作開始時のrequestIdを保持し、非同期応答後に`completePreparedPreviewCheckout`へ渡す。この処理は現在のカートと照合し、不一致・削除・有効期限外なら保存・削除・計測を行わず終了する。画面は既存の注文内容確認エラーを表示する。一致した場合だけ既存の完了処理へ進む。通常の特典確定結果の整合検証も引き続き行う。

## 検証

遅延応答を実際の支払画面ハンドラーへ渡す7件のテストを追加。新しい同一商品／別商品カート、カート削除、変更のない通常応答／利用不可応答、明示的な特典不使用の選択、古い特典確定結果を検証する。修正前は新しいカートを誤完了する2件が失敗し、修正後は7件すべて成功。拒否時は保存領域全体を比較し、新しい入力と計測が変更されないことを確認する。

`pnpm check:ci`成功：782件成功、外部DB等の138件skip。静的検査・型・lint・本番ビルド成功。遅延は制御したPromiseで再現し、ブラウザーや外部サービスの障害設定は変更していない。表示要素・文言・CSSは変更していないため、新しい視覚検証は行っていない。

## 範囲と戻し方

ブラウザーのrequestIdはテスト操作の対応付けであり、認証・実決済の証拠ではない。サーバーで既に記録された古いテスト紹介注文を取り消す処理ではない。本番Shopify、価格・在庫の検証、認可、外部接続は変更しない。カートrequestIdが変わらない住所編集等を検出する仕組みは本変更に含めない。

revertで戻せる。DB・環境変数・既存v1保存形式の移行は不要。
