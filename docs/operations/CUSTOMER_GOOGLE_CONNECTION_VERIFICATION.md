# 顧客用Googleログインの実接続検証

2026-09-13。mainの `7a1f4cc6b2f71c222de5010370972f3fe78036e0` に対し、実Googleアカウント1件、実ブラウザー、隔離したローカルPostgreSQLで確認しました。このPRは検証記録のみで、アプリケーションコード・依存関係・マイグレーションの変更はありません。

## 接続範囲

- 運営者用とは別のGoogle CloudプロジェクトとWeb OAuthクライアントを作成しました。表示名はBLOOM BOX、公開範囲はExternal / Testing、テストユーザーは所有者本人の1件です。Googleの利用者データポリシーへの同意後に作成し、一般公開はしていません。
- 登録したコールバックは `http://localhost:3000/api/customer-auth/callback/google` のみです。顧客用の認証秘密値も運営者用と分離し、既存の設定検証で分離を確認しました。
- スコープは `openid email profile`。Googleの同意画面には名前・プロフィール写真・メールアドレスが表示されました。アプリケーションが利用するプロフィールは名前・メールの短期セッション用スナップショットであり、写真やGoogleトークンは保存しない既存実装です。
- 新しいローカルDBへ既存の0001〜0022を適用しました。アプリ接続は `bloombox_application` の権限を持ち、superuser・DB作成・ロール作成・レプリケーション権限を持ちません。
- ランタイムはPreview、新規注文受付は無効です。認証情報は隔離作業ツリーのGit対象外設定と所有者のみが読めるローカルファイルに保存しました。元リポジトリの環境ファイル、運営者OAuth設定、本番・Vercelの設定は変更していません。

## 実ブラウザーとDBで確認したこと

| 操作 | 結果 |
| --- | --- |
| 初回のGoogle同意をキャンセル | 再試行できるログインエラーへ戻り、顧客・ID対応・監査・注文は各0件 |
| Googleで初回ログイン | `/account` に本人のプロフィールと注文がない状態を表示。顧客1件・ID対応1件・監査1件 |
| 顧客ログイン中に `/operations` を別タブで開く | 運営者用ログイン画面を表示。顧客セッションでは運営者として認証されない |
| 顧客DBのみ停止してマイページを再読込 | プロフィールや空の成功履歴を表示せず、再試行可能なエラーを表示 |
| DB再起動後に再試行 | 同じセッションでマイページが復旧 |
| ログアウトを一度操作し、別タブを再読込 | 両方でログイン画面へ戻り、プロフィールを表示しない |
| 同じGoogleアカウントで再ログイン | 既存顧客を再利用。顧客・ID対応・監査は各1件のまま |
| 検証DBで顧客のセッション版を1から2へ更新し、両タブを再読込 | 旧セッションを拒否し、ログイン画面を表示 |
| 失効後にGoogleで再認証 | 同じ顧客で利用を再開し、重複登録なし |
| 再度ログアウトし、ブラウザーの戻る・マイページ再訪・再読込 | 戻る操作ではGoogleのアカウント選択画面へ遷移。マイページの再訪・再読込ではログイン画面を表示 |

最終DB件数は顧客1、ID対応1、監査1、連絡先0、マーケティング同意0、注文0です。検証後はBloomBoxからログアウトし、失効後のセッション版2を保持しました。Googleアカウント自体からのログアウトではありません。

マイページのHTTP応答で `Cache-Control: private, no-store, max-age=0` と `X-Robots-Tag: noindex, nofollow` を確認しました。[識別情報を含めない結果一覧](evidence/customer-google-connection-20260913.json)を添付します。これは実施記録であり、自動再現テストや本番稼働の証明ではありません。

## 停止・ロールバック

ローカルの `CUSTOMER_ACCOUNT_ENABLED=false` を反映して再起動すると入口を閉じられます。顧客用秘密値を更新すると既存セッションを一括失効できます。顧客ID・監査記録を削除する必要はありません。Google側のテストクライアント停止は顧客用プロジェクトに限定し、運営者用に影響させません。検証記録を戻しても外部設定は自動では戻りません。
