# 取消・返金の運用

自作注文（Stripe）の取消・返金・返品・再配送を、担当者が行う手順です。判断の根拠は [ADR 0016](../architecture/adr/0016-native-refunds-and-cancellations.md) です。取消期限・返品や再配送の費用負担などの条件は事業判断（P0-08）が必要で、この手順はそれを決めません。

## 前提

- 返金はStripe管理画面で行います。BloomBoxの画面から返金はできません。
- 発送の保留・取消は [自作注文の発送運用](NATIVE_FULFILLMENT.md) の画面で記録します。取消は返金を行いません。
- Stripe管理画面の担当者アカウントは個人ごとに発行し、返金の権限を必要な担当者だけに付与します（P0-10）。
- 返金の反映は、Webhookの処理を待って確認します。管理画面の操作だけでは完了としません。

## 発送前に取り消す

1. 発送管理画面で対象の注文を開き、「保留にする」を理由付きで記録します。発送準備・発送が止まります。
2. 返金する場合は、Stripe管理画面で対象の支払から、全額または一部を返金します。返金額は支払額を超えられません。
3. 数分後、発送管理画面の支払状態が「返金済み」または「一部返金済み」になったことを確認します。変わらない場合は、[障害対応手順](COMMERCE_WORKER_INCIDENTS.md) で失敗した通知や滞留を確認します。
4. 発送管理画面で「発送を取り消す」を理由付きで記録します。
5. 実物が再販できる状態で残る場合だけ、商品・在庫管理の「数量訂正」で販売用在庫を戻します。返金だけを理由に戻しません。

返金した注文は、支払が「支払確定」だけの状態ではなくなるため、発送準備・発送を記録できません。

## 発送後の返品・受取拒否

- 発送の状態は「発送済み」または「配達済み」のまま残します。返送の状態は記録しません。
- 返金の要否と金額は、事業条件（P0-08）に従います。返金する場合はStripe管理画面で行い、反映を確認します。
- 生花は返品を受けても販売用在庫に戻しません。
- 対応の経緯は、サポートの記録に注文番号と識別子だけで残します。

## 再配送

- 配送会社の再配達（同じ追跡番号）で対応します。追跡番号が変わった場合は、発送管理画面の「配送会社・追跡番号を訂正する」で記録します。
- 別の箱を送り直す再発送は、現在の画面では記録できません。必要になった場合は、開発担当と対応を決めてください。

## 異議申し立て（チャージバック）

- 回答はStripe管理画面で、期限までに行います。
- 未対応の一覧は、[照合レポート](FINANCE_RECONCILIATION.md) の `OPEN_DISPUTES` で確認します。
- 異議申し立て中の注文は、支払が「支払確定」だけの状態ではないため、発送準備・発送を記録できません。発送前であれば、結論が出るまで保留にします。

## 確認と記録

- 返金の後は、照合レポートの `REFUND_TOTAL_MISMATCH` と `REFUNDS_NOT_SETTLED` を確認します。
- Stripeで成功した返金が後から失敗に変わると、BloomBoxはその通知の処理を拒否し、失敗した通知としてWorker Incidentに現れます。BloomBoxの記録は返金成功のまま残るため、Stripeの状態を確認し、[障害対応手順](COMMERCE_WORKER_INCIDENTS.md) に従って対応します。台帳やDBを手で変更しないでください。
- 顧客への連絡は、Stripeの返金メールの設定と、サポートの窓口（P0-16）で行います。Issueやチャットに顧客の氏名・住所・連絡先を書きません。
