# 運営管理画面

2026-09-17。管理画面を `/operations` に集約。顧客用マイページとは独立したGoogle認証・Cookieを使います。通常の運営業務の入口を揃える変更であり、本番販売・配送・決済や担当者権限を自動で有効化する変更ではありません。

## 機能と経路

| 画面 | 利用できる機能 | データ・権限 |
| --- | --- | --- |
| `/operations` | 過去30日（日本時間）の注文数・受注額・発送前・返金のある注文、日別グラフ、最近の注文、業務へのショートカット | Google認証済みなら入場可能。担当者未登録時は登録案内のみ。集計・注文は顧客サポート権限が必要 |
| `/operations/orders` | 自作注文番号／UUIDの完全一致検索、注文・支払・発送の独立した状態フィルター、20件ずつのページ送り、購入者履歴への移動 | `DATABASE_CUSTOMER_SUPPORT_URL`、`customer_support_operators`。住所・電話・メール・ギフト本文を表示しない |
| `/operations/customers` | 既存の顧客検索・状態フィルター・購入履歴 | 既存の顧客サポート権限と参照監査を維持 |
| `/operations/catalog` | 既存の商品登録・編集、価格・送料、公開状態、在庫補充・訂正 | `DATABASE_CATALOG_MANAGER_URL` と期限付き商品管理権限。更新の競合・冪等性・監査は既存処理を維持 |
| `/operations/reports` | 7／30／90日の日別集計、件数と金額の表、取消・決済済みの件数 | 顧客サポート権限。集計取得も監査が成功してから表示 |
| `/operations/settings` | 本人確認・担当者登録状況、業務接続の設定状態、広告・通知・会員ランクと運用上の制約 | Google認証が必須。秘密値、他担当者の識別子、接続文字列を表示しない。設定有無は疎通・権限を保証しない |
| `/preview/operations` | サンプルのダッシュボード。`state=empty`／`state=unavailable` で状態確認 | preview環境のみ。架空の固定データで、セッションやDBに触れず、認証・権限を発行しない |

旧Shopify向け注文・権限画面は互換性のため残しますが、新しい主メニューでは自作注文へ案内します。

## 集計の定義

- Stripeをcommerce providerとするJPYの注文のみ。顧客との紐付けがない注文も注文一覧・集計に含め、所有者を推測しません。匿名化済みの顧客への履歴リンクは表示しません。
- **受注額**は、期間内に作成された注文の注文時合計（取消済みを除く、送料・税込）。入金額・純売上・返金後金額ではありません。
- **決済済み**は、支払状態の集合が `CAPTURED` のみの注文。複数状態を勝手に1つへ縮約しません。
- **発送前**は注文確定・決済済みで、未発送／準備中／準備完了／保留の発送状態を持つ注文。選択期間内に作成された注文が対象で、全期間の滞留件数ではありません。
- 期間は日本時間の当日を含む7／30／90日。開始日0時〜DBの現在時刻で取得。将来の注文は含めません。日別の空の日は0件として補います。集計時刻を画面に表示します。
- 注文ごとに支払・発送の状態を先に集約し、複数レコードのJOINによる金額の水増しを防ぎます。整数金額の安全範囲を超えた場合は失敗扱いです。
- 読み込み失敗・権限なし・未登録・0件は別の状態です。失敗時に架空の数字や0件へ置き換えません。

## セキュリティと責務

Orderの読み取り契約とPostgreSQL実装を、Shared securityが既存の `withCustomerSupport` へ接続します。UIはSQL・権限・金額算定を持ちません。担当者未登録では業務用DBを開かず、登録済みでも専用の期限付き権限をトランザクション前後に検査します。顧客認証・商品権限だけでは注文や集計を読めません。

既存の `HISTORY` 参照監査を自作注文履歴の横断参照・集計にも適用します。一覧は返却した顧客IDの重複を除いて記録し、ゲスト・匿名化済みは紐付けを記録しません。集計は個人を返さないため顧客ID配列を空にします。監査保存失敗時にはデータを返しません。検索文字列・注文番号・集計値そのものは監査へ保存しません。追加のDB権限・スキーマ変更はありません。

レイアウトはナビゲーション専用。各ページの入口と各データ操作の両方で権限を確認します。認証済み未登録者が業務ページを開いたときは `/operations/settings` へ案内し、ログインループを防ぎます。ログイン後の戻り先は明示されたローカルパスだけです。管理ページは既存のprivate/no-store・noindex・同一Originポリシーを継続します。

## 公開接続で残る作業

- 本人確認済みGoogle subjectと内部operator UUIDの対応付け。
- 承認済み担当者の顧客サポート／商品管理権限と、それぞれの専用DB接続。一般アプリや顧客DBの資格情報を管理業務へ流用しない。
- 実環境での権限失効、商品編集・在庫調整、顧客・注文の閲覧の確認。
- 発送登録・追跡番号更新はADR 0015／Issue #124に従う未完機能。今回の注文画面は状態参照のみで、架空の発送ボタンは置かない。
- 返金はADR 0016に沿ってStripe管理画面で行い、Webhookの反映を確認する。画面からの返金、通知メール、CSV、顧客メモ、権限の自己付与は今回実装していない。

`pnpm check:ci` 成功（通常1,185件、型・Lint・静的検査・本番ビルド）。独立したローカルPostgreSQLでDB全体227件成功。既存のルーティング回帰、隔離PostgreSQLの専用ロールを使う実クエリで、絞り込み、同日時のページ送り、期間境界、重複集約、匿名化、ゲスト、旧Shopify除外、権限失効、監査失敗を確認しました。表示記録は [デザイン検証](../design/VERIFICATION.md) を参照。実機Safariと実Stripe購入はこの検証の対象外です。

戻す場合は本変更のコードをrevert。DB移行・データ削除は不要です。今回作成した監査記録は保持します。接続障害や権限停止を画面表示の修正だけで迂回しないでください。
