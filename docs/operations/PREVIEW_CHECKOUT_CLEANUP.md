# テスト購入完了後の入力情報削除

2026-09-12。対象はsessionStorageを使うテスト購入のみ。Shopifyの実注文・支払状態・本番の保持方針は変更しない。

## 問題と変更後の動作

完了情報を書き込んだ後に入力情報の削除が失敗すると、支払画面が保存失敗を表示していた。削除位置によっては購入準備も消え、同じ操作で再開できなかった。完了画面も残存データを調べず、個人情報を削除したと表示していた。

完了情報の書き込み後の削除失敗は専用の型付きエラーで区別し、保存済みの完了画面へ進む。完了画面は現在の保存領域から「削除済み」「削除待ち」「保存内容が変化」を読み取り、実態に合う案内を表示する。削除待ちはボタンから繰り返し試せる。再試行はテスト決済・紹介特典確定・購入計測・完了情報の再書き込みを行わない。

## 保護と限界

- 削除直前にも完了情報のrequestIdと現在のカートを照合。別のカート、不正なカート、置換された完了情報、識別子のない旧完了情報に紐づく残存データは、この画面から削除しない。
- 確認同意→購入者情報→購入準備→カートの順に削除し、途中で失敗しても購読画面へ変更を通知する。
- 保存領域にトランザクションはないため、一部の削除は先に完了する。完了情報の保存自体が失敗した場合は、入力情報を削除せず従来の保存再試行を案内する。
- エラー文に例外詳細や個人情報を含めず、新しい送信・保存先を追加しない。完了情報の既存v1形式を維持する。
- ブラウザーの完了情報はテスト用であり、実決済の証拠にはならない。ブラウザー全体や別タブの情報を削除したとは表示しない。
- 保存機能自体が利用できない間は既存の読み取り不能画面が優先される。操作途中の読み取り権限変更の全面的な保証は対象外。

## 検証

追加15件：4箇所の削除失敗、保存失敗、削除だけの再試行、繰り返し実行、完了情報と購入計測の保持、別カート／不正カート／置換・旧完了情報の保護、実際の支払・完了画面ハンドラーの遷移、誤った削除済み表示の抑止。修正前の画面へ戻した検証では6件中5件が失敗し、修正後は全件成功。

`pnpm check:ci`成功：790件成功、外部DB等の138件skip。型・lint・静的ポリシー・本番ビルド成功。関連する既存の読み取り不能テストを含む59件も成功。

実際の完了画面部品と共通CSSを静的HTMLに出力し、Chromeの320px幅で目視確認。横幅320px、削除ボタン高さ68pxで横溢れなし。この見本はボタンを動作させるものではなく、操作と例外の検証は単体テストで実施。実ブラウザーの保存設定変更、Shopify実決済E2E、ホスト先へのデプロイは行っていない。

## 戻し方

本変更をrevertする。環境変数・DB・保存形式の移行は不要。削除済みの入力情報はrevertしても復元されない。未削除情報が残る場合、旧画面の削除完了表示は信用せず、タブ終了など既存の保存領域管理が必要になる。
