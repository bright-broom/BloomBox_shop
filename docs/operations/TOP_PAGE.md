## 編集場所と単一の参照元

- `content/home.json`：見出し、FAQの選択ID、案内ページ参照、お知らせ、承認済み写真・比較仕様・レビュー。`home-content.ts` が起動/ビルド時に検証する。
- `content/storefront.json`：FAQ・包装・到着時対応の本文。トップへコピーしない。参照IDの削除・重複・不整合は検証で拒否される。
- お届け希望日は `modules/fulfillment/public.ts` の既存関数を使用。UIに日数や地域別ルールを複製しない。トップはリクエストごとの描画で、翌日へ進んだ後の再読み込みにも追従する。
- M/Lの価格・送料・合計は既存の商品情報とpreviewTotals。今回の編集用contentに価格を追加しない。
- コンポーネントはServer Componentとnative details。クライアントライブラリ、新規API、DB変更、環境変数追加はない。

## お知らせの追加・終了

技術担当が営業側で確認した原稿をPRにし、レビュー・配備後に公開URLで確認する。GitHub更新だけでは現行Vercelへ自動配備されない。

`announcements`へ次の形で登録する。例は仕様説明であり実際の配送遅延の告知ではない。

```json
{
  "id": "delivery-information",
  "title": "お届けについてのお知らせ",
  "body": "承認された案内文を記入する。",
  "href": "/shipping-returns",
  "severity": "important",
  "startsAt": "2026-10-01T09:00:00+09:00",
  "endsAt": "2026-10-02T09:00:00+09:00"
}
```

`severity`は`info`または`important`。終了日時は必須、開始より後とする。日時はUTCか明示オフセット付きで登録し、通常は日本時間`+09:00`を使う。期限後は次のリクエストから非表示。開いたままの画面を自動更新する機能やプッシュ通知はない。取り下げは項目を削除して再配備する。リンクは検証されたサイト内パスだけを許可する。

## 写真・比較仕様・レビューの登録

- `gallery.items`：`id / productSlug / status / src / alt / caption`。`status: approved`かつ公開カタログに該当商品があるものだけ表示。`draft`は非表示。実物・撮影条件・画像利用権を確認してから承認する。
- `comparison.sizes`：`size: M または L / status / description / facts: [{label, value}]`。承認された実測値と選び方を登録する。案画像から実寸やボリュームを推定しない。
- `reviews.items`：`id / status / quote / displayName / verifiedPurchase / publicationConsent`、必要なら`photo: {src, alt, caption}`。購入確認と掲載同意の両方がない承認済みデータをスキーマで拒否する。これらのフラグはコードレビューされた編集者の確認結果であり、注文DBによる自動証明ではない。
- 画像は`public/images/products/`配下のjpg/jpeg/png/webpのみ。画像が存在することをcontentテストで検査する。無制限の外部URLやSVGを許可せず、新しい画像ホストは追加していない。
- 公開JSONには匿名化済みの表示文と公開を許諾された素材だけを入れる。メール、注文番号、同意書、照合元はGitHubへ入れない。確認記録は担当者の権限管理された場所に保管する。
- レビュー取り下げは対象項目を削除して配備・公開確認する。写真の許諾も撤回された場合は、公開ファイルと配信キャッシュの削除を含めて対応する。`draft`化は画面上の非表示だけで、Git履歴や公開ファイルの削除ではない。
