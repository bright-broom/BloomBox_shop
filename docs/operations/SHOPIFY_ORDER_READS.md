# Shopify注文・返金の正式データ取得

2026-09-11時点。署名済み通知から対象店舗のAdmin GraphQL APIを読み、注文・返金の最新データを検証する内部処理を実装しました。注文の購入者との関連付け、入金・返金・配送の状態反映はまだ行いません。

## 使用範囲と設定

`ReadShopifyReference` → `ShopifyAdminOrderReader`で参照します。`getShopifyReferenceReader()`は初期状態では`null`です。隔離環境で`BLOOMBOX_SHOPIFY_ADMIN_MODE=read`を指定すると取得処理を組み立てます。公開APIやInbox消費ワーカーには接続していないため、設定だけで通知が処理済みになったり、購入経路が変わったりすることはありません。

| 設定 | 条件 |
| --- | --- |
| `BLOOMBOX_SHOPIFY_ADMIN_MODE` | 未指定/`disabled`で無効。`read`のみ許可 |
| `SHOPIFY_STORE_DOMAIN` | 対象の`*.myshopify.com`店舗。通知の保管先と一致させる |
| `SHOPIFY_ADMIN_ACCESS_TOKEN` | 対象店舗のAdmin APIアクセストークン。署名鍵やStorefrontトークンとは別。秘密管理から注入し、`NEXT_PUBLIC_`やNext.js設定の`env`に置かない |
| API版 | `2026-07`固定。レスポンスのAPI版も一致を確認 |

読み取り権限だけを付与します。注文/返金は`read_orders`が前提で、取得するvariant情報についても実店舗の権限で照会が通ることを確認します。通常の注文アクセス期間を超える履歴には別途`read_all_orders`の承認が必要です。権限不足を空データや支払済みと解釈せず失敗させます。実際の権限設定、認証方式・更新手順、加盟店接続テストは未実施です。[公式Order仕様](https://shopify.dev/docs/api/admin-graphql/2026-07/objects/Order)。

## 取得・検証する内容

- ホストを設定済み店舗に固定し、Adminトークンで`shop.myshopifyDomain`と指定IDの`node`を同じ問い合わせで取得。店舗名、参照ID、オブジェクト種別を照合する。
- 注文は更新日時、テスト注文か、取消日時、表示用の決済状態、作成時/現在の合計、受領額、返金額、明細ID・variant ID・数量・現在数量・作成時単価を取得する。
- 返金は返金ID・更新日時と関連注文、取引ごとのID・種別・状態・テスト区分・金額を取得する。返金要求が存在することと、資金の返金成功を同一視しない。[公式Refund仕様](https://shopify.dev/docs/api/admin-graphql/2026-07/objects/Refund)。
- 金額は店舗通貨と購入時通貨の両方がJPYかつ同額の、非負の安全な整数だけを扱う。少数端数、桁あふれ、通貨不一致を拒否する。店舗の元価格と現在価格は別々に保持し、独自に足し引きして支払済みを推定しない。
- 注文明細と返金取引はそれぞれ100件まで。次ページがある場合やIDの重複は、部分データを成功扱いにせず拒否する。大量明細の対応が必要になるまでページング基盤は追加しない。
- 決済状態がnull、削除済みvariantがnullの場合はそのまま返す。後続の関連付け・状態反映で保留するためで、購入準備への一致を意味しない。テスト注文・取引の区分も落とさない。

氏名、メール、住所、ギフト本文、注文属性、決済手段の詳細、領収データは問い合わせません。応答に余分なフィールドが含まれても戻り値に残しません。トークン、応答本文、GraphQLエラーメッセージをログへ出しません。

## 障害・遅延・再実行

1回の読み取りは5秒、本文は256,000バイトまでです。宣言サイズだけでなく受信中のサイズも制限し、リダイレクトは拒否します。応答待ちと本文待ちの両方に締切を適用し、キャンセル完了待ちで応答が止まらないようにします。

対象外店舗・不正参照は外部通信前に`InvalidShopifyReferenceError`。店舗内で見つからない参照は`ShopifyOrderNotFoundError`。通信断・制限・権限不足・API版不一致・データ不備・部分成功のGraphQLエラーは`ShopifyOrderUnavailableError`です。いずれも通知を処理済みにしません。見つからない理由は削除、アクセス範囲、権限、タイミングの可能性があり、通知が不要になったとは判断しません。

この境界は読み取りのみで自動再試行しません。将来の処理ワーカーが既存Inboxの遅延再試行を利用します。古い通知も通知本文の状態を採用せず、その時点のAPIデータを取得します。ただし取得後の同時更新まで固定するものではなく、将来の反映処理には更新順序・重複・競合の制御と再照合が必要です。

## 次の実装条件

店舗内の正式データであることと、BloomBoxの購入準備に属することは別です。現在の購入準備ID属性だけでは後者を証明できません。購入試行・カート・注文の信頼できる関連付けと所有権確認を完成させるまで、この結果から注文・入金・配送を作成しません。

後続は購入試行との厳密な関連付け、商品/数量/価格/割引/税/送料の照合、注文・入金・返金・配送のトランザクション反映、監査/Outbox、未着通知の再照合、滞留監視・保持期限です。返金の部分成功・処理中・失敗やテスト取引を含むケースを実店舗で検証します。本番公開判定は引き続き無効です。

## 検証とロールバック

合成レスポンスで店舗/ID/API版/通貨/金額/部分データの拒否、個人情報の除外、保留・成功・失敗の返金、署名済みの遅延通知からの最新注文取得、サイズ上限、タイムアウト、キャンセルを検証します。実店舗の注文を取得した証跡ではありません。

マイグレーション・新規依存・DB書き込みはありません。`BLOOMBOX_SHOPIFY_ADMIN_MODE=disabled`で組み立てを停止し、必要に応じてこの差分を戻します。既存Inboxの通知・暗号鍵・購入試行は保持します。
