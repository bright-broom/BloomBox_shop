# 実Googleの2顧客と検証用注文の表示分離

2026-09-13。実行時コードはmainの `7a1f4cc6b2f71c222de5010370972f3fe78036e0` と同じです。顧客専用Google OAuthのExternal / Testingへ指定された2人目を追加し、本人のパスキー確認を経てログインしました。1人目とは別の顧客として登録されました。

## 検証範囲と注文の作り方

正規オリジンは `http://localhost:3000`、既存の隔離ローカル顧客DBを使用しました。Google認証・Cookie・マイページ・注文詳細は実装済みの処理をそのまま使い、テスト用のログイン迂回は追加していません。

注文は補助スクリプトで作成した架空の2件です。実Googleログインによって既に存在する顧客IDをサーバー側の購入処理へ渡し、既存の購入準備・決済イベント処理・購入者作成を通しました。商品名には「接続確認用」を付け、受取人とメッセージも架空です。価格はPreviewカタログのスナップショット、送料は検証用の1,000円です。

**Stripeへ通信せず、合成した入金イベントを直接処理しています。画面の「お支払い済み」は検証用の状態で、実際の支払い・発送はありません。** ブラウザーでの購入、認証Cookieから購入者への紐付け、Stripe署名検証・決済画面・在庫予約を通した試験ではありません。補助スクリプトはローカル専用で、公開API・アプリケーションコードには追加していません。

## 実ブラウザーで確認した結果

同じブラウザーでBloomBoxからログアウトし、Googleのアカウント選択から顧客を切り替えました。

| 操作 | 結果 |
| --- | --- |
| 顧客Bで初回ログイン | 本人プロフィールと空の注文履歴を表示 |
| 検証用注文作成後、顧客Bで履歴を再読込 | 本人のL注文9,000円の1件のみ |
| 顧客Bが本人の詳細を開く | Lの商品8,000円・送料1,000円・合計9,000円を表示 |
| 顧客Bが顧客Aの詳細URLを直接指定 | 「ご注文を表示できません」。商品・金額を表示しない |
| ログアウト後、顧客AでGoogle再ログイン | 本人のM注文5,000円の1件のみ |
| 顧客Aが本人の詳細を開く | Mの商品4,000円・送料1,000円・合計5,000円を表示 |
| 顧客Aが顧客Bの詳細URLを直接指定 | 同じ非表示画面。商品・金額を表示しない |
| 最後にログアウトし、両方の詳細URLを直接指定 | どちらも非表示。マイページへ戻るとログイン画面 |

最終件数は顧客2・Google ID対応2・注文2・監査6・連絡先0・マーケティング同意0です。再ログインによる顧客の重複はありません。個人情報を含む画面画像・実識別子は公開記録に含めません。

## 自動テストとの関係

[購入者紐付けの回帰テスト](PURCHASE_CUSTOMER_BINDING.md)では、これとは別の使い捨てDBと合成顧客で、顧客A・B・ゲストの3注文、同じプロバイダー識別子、重複イベント、限定DBロールでの履歴・詳細の分離を確認しました。通常890テスト、DB191テスト、静的検査・型・Lint・ビルドが成功しています。

今回の実ブラウザー確認は、購入から決済までの全経路や本番HTTPSの動作証明にはなりません。次はStripeテスト決済と認証済み購入者の紐付けを通した接続検証が必要です。本番設定・本番の注文受付停止・運営者OAuthは変更していません。

## 保存と停止

検証終了時はBloomBoxからログアウトしました。顧客ID・検証用注文・監査は隔離ローカルDBに保持し、本番への移行対象にしません。Google側の公開範囲はTestingのままです。ローカル認証を止める場合は `CUSTOMER_ACCOUNT_ENABLED=false` を反映して再起動し、必要に応じて顧客用秘密値を更新します。記録をGitで戻しても、外部設定や保存した検証用注文は自動削除されません。
