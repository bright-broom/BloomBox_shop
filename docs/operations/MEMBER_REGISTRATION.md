# 新規会員登録

2026-09-19。実装済み。一般公開はGoogle OAuthの公開（P0-22、#132）待ち。規約・ポリシー本文は法務確認（P0-16）待ちの案。

## 背景

会員は、以前からGoogleログインの初回に自動で作成されていた。ただし次の問題があった。

- 画面に「新規会員登録」の入口がなく、初めての人に登録できることが伝わらなかった。
- 登録時に利用規約・プライバシーポリシーへの同意を取っておらず、同意の記録もなかった。
- 初回ログインでも、既存の会員と同じ画面になっていた。

## 流れ

```mermaid
flowchart TD
  Entry[トップの会員案内・ログイン画面・フッター・スマホメニュー] --> Register[/account/register 新規会員登録]
  Register -->|Googleで登録する| Google[Googleで本人確認]
  Google -->|初回はアカウントを作成| Welcome[/account/welcome]
  Welcome -->|規約とポリシーを確認し、チェックして同意| Record[同意を版つきで記録]
  Record --> Account[/account 登録完了の表示]
  Welcome -->|同意しない| Logout[ログアウト]
  MyPage[マイページの各画面] -. 現行版に未同意 .-> Welcome
```

- 登録にはパスワードを使わない。Googleから受け取るのは、アカウントの識別子、確認済みメールアドレス、名前だけ（従来どおり）。
- 同意は `customer_consents` に次の値で記録する。スキーマは変更していない。
  - `purpose = 'MEMBERSHIP_TERMS'`
  - `status = 'GRANTED'`
  - `policy_version` = `content/storefront.json` の `agreementVersion`
  - `source = 'MEMBERSHIP_REGISTRATION'`
  
  監査ログには `customer.membership.agreed` を残す。
- 同意の送信は次の条件をすべて満たしたときだけ受け付ける。
  - 同一オリジンからのフォーム送信
  - ログイン中の本人
  - チェックがある
  - 画面に表示した版が現在の版と一致する（古い画面から新しい版に同意したことにしない）
- 同じ版への再送信や同時送信は、アカウント行のロックで直列化する。記録は1件だけになる。
- 退会時は、最新の同意に対する `WITHDRAWN`（`ACCOUNT_CLOSURE`）を記録する。
- マイページ（トップ・各セクション・注文詳細）は、現行版に未同意なら同意画面へ誘導する。登録データの出力（`/account/export`）は本人の権利として誘導の対象外。
- 同意状態を読み込めないときは、各画面の既存のエラー表示に任せる。同意画面は再読み込みの案内を出す。

## 規約を改定するとき

1. `content/storefront.json` の本文を更新する。
2. `agreementVersion` を新しい値に変える（英小文字・数字・ハイフン、40文字以内。例 `2026-10-01`）。
3. 既存の会員は、次にマイページを開いたときに「利用規約・プライバシーポリシーを改定しました」の画面で再同意する。

`publicationStatus` を `approved` にするときは、`-draft` で終わる版を使えない（スキーマで拒否する）。正式版の公開で全会員が再同意することになる。

## 対象外・残課題

- 購入手続き、会員割引、ギフト入力での住所帳の読み込みは、同意を条件にしていない。規約上、会員サービスの利用に同意を必須とするかは P0-16 で確認する。
- 同意しない場合、Googleログインの時点で作成されたアカウントは残る。削除はお問い合わせで受け付ける（マイページの退会は同意後に利用可能）。
- Googleの同意画面は「テスト中」で、登録テストユーザー以外は登録できない（P0-22、#132）。
- Google以外の登録方法（#156）、登録後のメール通知は未実装。

## 検証

- 単体テスト
  - 版の判定（初回、同じ版、改定、撤回、不正な版）
  - 同意の記録条件（チェックなし、古い版、他オリジン、フォームで送られた偽の顧客ID）
  - 画面（入口の表示、未同意時にデータを読む前に誘導、同意画面の版・戻り先・文書リンク、同意済みなら戻る）
  - サーバーアクションの戻り先とエラーの伝え方
  - `approved` にしたときの版の検査
- DBテスト（CIで実行）：application roleでの記録、同時送信で1件、版の更新、他の顧客からの分離、監査、退会時の撤回、退会後の拒否
