# 担当者の承認フォーム

2026-09-12。[注文一覧](OPERATOR_FULFILLMENT_INBOX.md)から開く確認画面に、確認内容の記録フォームと Server Action を接続しました。事業方針 `FULFILLMENT_INTAKE_POLICY.approval` は **PENDING のまま**です。操作可能なフォームは表示せず、直接送信も拒否します。実 Google 接続・実担当者権限の登録や、発送実行は行っていません。

## 表示と送信の境界

- 検証済み Google セッション、明示的な担当者対応付け、店舗権限で確認対象を取得します。事業方針が承認済みで、表示用判定も承認待ちの場合だけ送信情報を発行します。表示判定は承認権限を与えません。
- 店舗・発送 ID・確認済み受付版・担当者 UUID・セッション期限・test/live 区分・サーバー発行の冪等キーを JWE に封入します。既存 AUTH_SECRET から目的と正規 Origin を分離して HKDF-SHA256 で鍵を導出し、jose の dir/A256GCM を使います。ブラウザーには平文の担当者 UUID や冪等キーを渡しません。
- 有効期限は発行から最大5分、かつ元のセッション期限までです。再ログイン・別担当者・別 Origin・区分違い・改ざん・期限切れでは使えません。在庫根拠の30秒期限を延長するものではありません。
- 明示的なチェック操作を必須にします。サーバーは現在のログイン、対応付け、正規 Origin、単一の確認情報とチェック値を検証し、追加の担当者・対象・版指定や重複フィールドを拒否します。Next.js の Server Action による Origin/Host 検証と既定の本文上限も維持します。
- 既存の専用 DB ロールと承認トランザクションへ渡し、現在の権限・受付版・入金・数量・在庫・配送情報・事業方針を再判定します。承認、監査、Outbox は原子的に保存されます。発送状態は変わりません。

暗号化は [EncryptJWT](https://github.com/panva/jose/blob/main/docs/jwt/encrypt/classes/EncryptJWT.md)、復号と登録済みクレームの検証は [jwtDecrypt](https://github.com/panva/jose/blob/main/docs/jwt/decrypt/functions/jwtDecrypt.md) を使用します。

## 再確認・再送

送信中は操作を無効化し、結果を読み上げ可能な通知として表示します。結果不明時は確認期限内に限り同じ画面の同じ確認情報で再送できます。期限後は確認画面を開き直して履歴を確認します。二重送信は同じ冪等キーで処理し、現在の前提も再検証します。保存後の画面更新だけが失敗した場合は、保存成功を失敗として扱いません。ログは固定の障害分類だけを出力します。

「最新の確認画面を開き直す」は保存済みの照合結果と履歴を読み直します。Shopify の再取得や照合処理を起動する操作ではありません。在庫根拠が古い場合は、照合側で新しい受付版を保存してから確認し直す必要があります。確認情報の期限切れや別画面からの再送では、過去の判断が残っていても再確認・競合になる場合があります。承認履歴を確認し、別キーを使って同じ版の承認を作り直さないでください。

プレビューは架空データの説明表示だけです。フォーム、認証、承認コマンド、実注文 DB には接続しません。

## 開いたままの画面の確認期限

READYのフォームに、日本時間の確認期限を表示します。期限はサーバーで在庫根拠の期限・元のセッション期限・暗号化した確認情報の期限の最も早い時刻にそろえます。準備時点で期限がない・不正・経過済みの場合は操作用のフォームを発行しません。日時は表示専用で、送信項目に追加した日時は拒否します。

画面を開いたまま期限を過ぎると、確認チェックと送信ボタンを無効にし、読み上げ可能な文章で開き直しを案内します。毎秒の読み上げ、フォーカスの強制移動、自動送信、自動照合は行いません。ページ復帰・フォーカス・表示状態の変更でも確認し、送信イベント時にも再確認します。経過時間の計測を併用するため、端末時計を戻しても、その画面の残り時間を延ばしません。タイマーとイベント監視は画面の破棄時に解除します。

送信中に期限を過ぎても、処理結果が返るまで送信中の表示を維持します。その後に成功が返れば成功を表示し、期限切れの失敗として扱いません。結果不明のまま期限を過ぎた場合は、再送せず承認履歴の確認へ案内します。

これは操作を補助する表示です。端末時刻や配信遅延で表示差が生じる場合があるため、サーバーの認証・認可・在庫・受付版・期限の再検証を引き続き必須にします。JavaScript停止や表示用日時の改変で承認できるようにはなりません。事業方針PENDINGは維持し、Shopifyの再取得や発送を開始する機能は追加していません。

期限表示の追加では `pnpm check:ci` が成功し、通常743件・静的検査・型・Lint・本番ビルドを確認しました。DB変更はないため隔離DB138件は今回再実行していません。タイマーの境界、時計の巻き戻し、ページ復帰、監視の解除、再送時の追加日時拒否をテストしています。

実コンポーネントと共通CSSを用いた隔離Chromeで、サーバー描画からのhydration、配信遅延後の期限切れ、320/1440px、横はみ出しなし、キーボードでの開き直し、期限後の送信イベント拒否、送信中の期限切れからの成功／結果不明を確認しました。合成Actionを使う表示テストであり、実Google・実注文・本番承認のE2Eではありません。

## 本番有効化の残件

実 Google の接続とログイン E2E、担当者別の監査を伴う権限管理、事業条件の承認、実店舗での承認済み条件下のブラウザー／プロバイダー E2E が必要です。[操作頻度の制限](OPERATOR_APPROVAL_RATE_LIMIT.md)は後続実装済みです。移行0015と専用権限の適用が必要です。セッション個別失効の制約は [Google ログイン](GOOGLE_OPERATOR_LOGIN.md) を参照してください。承認時の照合は保存済み根拠に対するもので、Shopify と DB の同時点を保証しません。発送コマンド・Inbox 完了・本番 Gate は別の実装／有効化対象です。
