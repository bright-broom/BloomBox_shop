# ADR 0014: 同意に基づく広告コンバージョン連携

- 状態: 実装方式として採用、2026-09-14。ユーザーの「各広告と連携できる仕組み」の依頼に対応。実アカウントへの送信は未有効化。
- 範囲: Google広告（Data Manager API）、Meta（Conversions API）、署名付きWebhookでの購入計測。

## 決定

Advertisingモジュールが同意・広告クリック情報・送信待ち記録を所有する。購入や決済の状態を変更しない。ブラウザに第三者SDKを読み込まず、顧客/受取人/贈る言葉/ログイン画面を外部の自動収集対象にしない。

同意前はクリックIDを保存しない。明示的な同意後、最初の広告クリックを最大30日間保持する。同意済みの直接訪問に識別子がなければ、後の広告ランディングで最初のクリックを追加できる。識別子は暗号化したサーバー記録、ブラウザにはランダムなHttpOnlyトークンだけを置く。広告URL全体、自由なUTM文字列、氏名、住所、メール、顧客ID、メッセージは記録/送信しない。

StripeのライブCheckout作成後、同意と購入意図の対応をAdvertising自身のトランザクションで保存する。重複した作成要求は媒体別の一意制約で吸収する。保存失敗は匿名化したエラーで観測し、注文を失敗にしない。広告記録とCheckoutは分散トランザクションにしないため、この保存が失敗した購入の計測は欠落し得る。購入手続きの再試行で回復可能。

専用workerはOrderの読み取り契約で、検証済みStripe処理が確定した、全額CAPTURED・未返金・未キャンセルのライブ注文だけを取得する。ブラウザリダイレクト、価格入力、マイページ閲覧、テスト決済を売上イベントとして扱わない。金額は確定時の税込・送料込み・割引後総額（JPY）。購入ID・発生時刻・金額を保存して再試行中も固定する。

各送信前に同意と注文を再確認する。送信の直前に同意撤回が完了していれば送らない。外部へ送信中のリクエストは取り消せない。撤回は過去の送信済みデータを外部から削除する処理ではない。

## 信頼性と拡張

永続記録、排他的lease、最大5回の送信、5分間隔、47時間の打ち切り。同じeventIdをGoogleのtransactionId、Metaのevent_id、WebhookのIdempotency-Keyに使う。正確な一度だけの通信は保証せず、媒体側の重複排除と組み合わせる。対象アカウントの指紋を保存し、設定変更で待機中の個人データを別アカウントへ転送しない。

外部HTTPは4秒上限・32KB応答上限・リダイレクト禁止。Google OAuth更新とAPI送信は別々に上限を適用。ログにトークン、クリックID、応答本文を出さない。受理は広告帰属の成功ではなく、requestId/traceIdで媒体側診断を確認する。購入後の返金訂正はこの段階では自動送信しない。

既存のOutbox/worker原則をAdvertisingの小さな送信待ちテーブルで適用する。別サービス、メッセージブローカー、ブラウザPixel、顧客名簿アップロードは追加しない。別媒体はAdvertisingDestinationを実装し、媒体設定・同意文言・テストを追加する。汎用Webhookはクリック情報を含まないため、そのままで任意媒体への帰属が完了するものではない。

## 有効化と切り戻し

初期値は無効。プレビューでは同意UIの状態だけを検証でき、識別子の永続保存・外部送信は行わない。ライブ設定には広告アカウントの権限/ID/秘密情報、migration 0026、DB権限、暗号鍵、定期worker、実媒体テストが必要。販売開始の既存ゲートを変更しない。

無効化は `BLOOMBOX_ADVERTISING_ENABLED=false`。停止後も保持期限の掃除を継続する。schemaは残し、注文/決済に触れずにアプリ変更をrevertできる。詳細: [広告連携の運用](../../operations/ADVERTISING.md)。
