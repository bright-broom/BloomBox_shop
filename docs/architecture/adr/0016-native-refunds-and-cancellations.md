# ADR 0016: 自作注文の取消・返金・返品・再配送の初期運用

- Status: Accepted implementation direction, 2026-09-16. 取消期限・返品/交換/再配送の条件（P0-08）、担当者の指名、本番販売開始の承認ではない。
- Extends: ADR 0009、0010、0015。
- Issue: #136（P1-02）

## 背景

Stripeの返金・異議申し立ては、署名検証済みのWebhookで受信し、冪等に反映する実装がすでにある。

- `refund.created`・`refund.updated`・`refund.failed` を受け、`refunds` を作成・更新する。
- 成功した返金の合計から `payments` の返金額と状態（支払確定・一部返金済み・返金済み・異議申し立て中）を更新する。
- 返金が成功した時点で、台帳に `REFUND` を1回だけ計上する。
- 返金額が支払額を超える通知や、通貨が異なる通知は拒否する。

一方、BloomBoxから返金を指示する処理はない。ADR 0015 の発送の取消は決済を変更しない。販売前に、誰がどこで返金するか、発送・在庫・通知との整合をどう取るかを決める必要がある。

## 判断

### 1. 返金はStripe管理画面で行う

- 全額・一部の返金は、返金権限を持つ担当者が、Stripe管理画面で対象の支払（PaymentIntent）から実行する。
- BloomBoxに、返金を指示するAPI・画面・返金権限を持つ制限キーは追加しない。
- 返金の確定は、Webhookの反映（`payments` の状態と返金額）で判断する。管理画面で操作した直後の表示を、BloomBoxの確定状態として扱わない。
- 担当者のStripeアカウントは個人ごとに発行し、返金の権限を必要な担当者に限る（外部設定、P0-10）。

理由：

- 返金額の上限（支払額を超えない）と、同じ返金の二重作成の防止は、Stripe側で保証される。
- 非同期の確定・失敗は、既存のWebhook処理と照合レポート（P1-04）で追跡できる。
- 独自の返金操作を作ると、制限キーへの返金権限の付与、二重送信の防止、結果不明時の復旧、担当者の権限と監査を新たに持つことになる。初期の注文数に見合わない。

### 2. 発送前の取消

1. 発送管理画面（ADR 0015）で「保留」にし、発送を止める。
2. 返金する場合は、Stripe管理画面で返金する。
3. Webhookが反映され、支払状態が「返金済み」または「一部返金済み」になったことを確認する。
4. 発送管理画面で「取消」を理由付きで記録する。

- 返金しない取消（例：お届けできない住所で連絡がつかない場合の扱い）の可否は、事業条件（P0-08）で決める。
- 支払状態が「支払確定」だけでない注文は、ADR 0015 の判定により準備・準備完了・発送を記録できない。そのため、返金後に誤って発送を記録することはない。

### 3. 発送後の返品・受取拒否・再配送

- 返送（`RETURNED`）への状態遷移は、初期は提供しない。発送の状態は「発送済み」または「配達済み」のまま残す。
- 生花は返品を受けても再販しない前提とする。返金の要否と金額は事業条件（P0-08）に従い、Stripe管理画面で返金する。
- 対応の経緯は、サポートの記録に注文番号と識別子だけで残す。
- 再配送は、配送会社の再配達（同じ追跡番号）で対応する。別の箱を送り直す再発送は、1注文1発送（ADR 0015）の範囲外とし、必要になった時点で複数箱（P2-04）と合わせて別のADRで決める。

### 4. 在庫

- 返金や取消を理由に、販売用在庫を自動で戻さない。
- 発送前の取消で実物が再販できる状態で残る場合だけ、担当者が商品・在庫管理の「数量訂正」で戻す。
- 予約の解放（ADR 0010）は未確定の購入準備だけに適用し、確定した注文には適用しない。

### 5. 通知と異議申し立て

- 返金の購入者への通知は、Stripeの領収・返金メールの設定で行う（P0-10のDashboard設定）。BloomBox独自の通知は P0-15 で決める。
- 異議申し立ての回答は、Stripe管理画面で行う。未対応の一覧は、照合レポート（P1-04）の `OPEN_DISPUTES` で確認する。

## 既知の制約（別課題）

- 成功した返金は最終状態として扱う。Stripe側で後から失敗に変わった場合、その通知は矛盾として処理を拒否し、再試行の後に失敗した通知としてWorker Incidentに現れる。BloomBoxの返金・支払・台帳は成功のまま残るため、担当者がStripeの状態を確認し、[障害対応手順](../../operations/COMMERCE_WORKER_INCIDENTS.md) に従って対応を記録する。状態と台帳を自動で訂正する処理（逆仕訳を含む）は別の課題とする。
- 返金は注文の状態（`CONFIRMED`）を変えない。注文の取消状態への遷移は、初期は行わない。
- 一部返金の内訳（商品・送料）は記録しない。

## 採用しない案

- **BloomBox内の返金指示画面：** 上記の理由による。販売量が増え、サポート画面（P1-01）から一連で操作する必要が出た時点で再検討する。
- **返金をきっかけに発送を自動で取消す：** 返金と発送の物理的な状態は別であり、返金時にすでに発送済みの場合がある。
- **返金をきっかけに在庫を自動で戻す：** 生花は再販できない場合がある。

## 残る検証

- 実Stripeのテスト環境で、全額・一部・失敗の返金 → Webhook → 支払・返金・台帳・照合レポートの一致を確認する（P0-18）。
- 合成データで、発送前の取消（保留 → 返金 → 反映の確認 → 取消）を演習する。

手順は [取消・返金の運用](../../operations/REFUNDS_AND_CANCELLATIONS.md) にまとめる。
