# ADR 0019: 購入者への取引通知

- 状態：実装方式として採用（2026-09-19）。ユーザーの「今日から営業できる状態にして、不足している機能を実装して」という依頼に対応。実際の配信は、事業者のメール配信アカウントと送信ドメインの設定後（初期状態は無効）。
- 範囲：注文確認メールと発送のお知らせメール（購入者宛て）。P0-15、#125。
- 関連
  - [ADR 0015](0015-native-fulfillment-operations.md)：発送管理
  - [ADR 0016](0016-native-refunds-and-cancellations.md)：返金はStripeのメールへ委譲
  - [ARCHITECTURE](../ARCHITECTURE.md)：外部送信はOutboxから行う

## 決定

- **送るもの**
  - 注文確認：署名検証済みのStripe通知で注文が確定したとき
  - 発送のお知らせ：運営者が発送を登録したとき
  - 返金・取消：独自メールは送らない。StripeのレシートとStripeの返金メールに委ねる（ADR 0016）。取消は現状、注文の状態遷移がないため対象外。
- **宛先**
  - Stripe Checkoutで購入者が入力したメールアドレスだけに送る。
  - お届け先（受取人）の氏名・住所は、宛先にも本文にも使わない。
  - 贈る言葉、住所、電話番号は本文に入れない。
- **イベント**
  - 既存の `order.confirmed`（決済確定と同じトランザクション）と、新しい `fulfillment.shipped`（出荷記録と同じトランザクション。発送管理ロールにOutboxへのINSERTだけを許可）を使う。
  - payloadにメールアドレス等の個人データは含めない。
  - 追跡番号は、payloadに入れる出荷の事実として扱う。
- **消費**
  - 既存の5分ごとの商取引ワーカー（`/api/internal/commerce-reconciliation`）が、決済通知の処理後に `deliverBuyerNotifications` を呼ぶ。
  - 通知の失敗はワーカー全体を失敗にしない。注文・決済・在庫の処理を優先する。
- **一度だけ送る**
  - 対象イベントを `FOR UPDATE SKIP LOCKED` とリースで取得する。
  - Outboxのイベントの識別子を配信事業者の冪等キーにする。そのため、送信後にDBの更新が失敗して再送されても、24時間以内は重複しない。
  - 送信直前に注文を読み直し、取消・未確定の注文には送らない。
- **再試行**
  - 送信は最大6回。間隔は1, 2, 4, 8, 16分と延ばし、上限は1時間。
  - 配信事業者が内容を拒否した場合（4xx）は再試行しない。
  - 鍵を読めない場合は再試行する。メールアドレスがない場合は送らない。
  - 結果はOutboxの `status` / `last_error_code` と監査ログ `notification.*.sent`（配信事業者のメッセージIDのみ）に残す。
- **送信期限**
  - 発生から48時間を過ぎたイベントには触れない。有効化した時点で、過去の注文へまとめて送らないため。
- **この消費者の位置づけ**
  - この2種のイベントの唯一の消費者とする。
  - 別の消費者を追加するときは、Outboxの `status` を共有せず、専用の配信記録を持つ。
- **配信事業者**
  - `EmailSender` のポートの背後に置く。最初の実装は Resend のHTTP API（無料枠あり、SDK依存なし、4秒タイムアウト、リダイレクト禁止、応答本文をログに出さない）。
  - 別の事業者へは、アダプターを差し替えて移行する。
- **有効化の条件**
  - `BLOOMBOX_NOTIFICATIONS_ENABLED=true` と runtime `production` の両方がそろったときだけ送る。
  - 送信元は認証済みドメインのアドレス（`NOTIFICATION_EMAIL_FROM`）に限る。

## 検討した代替案

- **Stripeのレシートだけに頼る**：決済の確認には使える。ただし、ギフトのお届け予定日や発送・追跡番号は伝えられない。
- **マーケティング用の配信基盤**：同意の扱いが異なる。取引メールと混ぜない。
- **SMTP**：依存ライブラリと接続管理が増える。HTTP APIのほうが、タイムアウトと冪等キーを確実に扱える。

## 影響と切り戻し

- DBスキーマの変更はない。権限の変更は、発送管理ロールへのOutbox INSERTだけ。
- `BLOOMBOX_NOTIFICATIONS_ENABLED=false` で送信を止められる。止めている間のイベントは `PENDING` のまま残り、48時間を過ぎると送らない。
- コードをrevertしても、注文・発送の記録は変わらない。
